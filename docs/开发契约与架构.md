> 本文件是所有并行开发者的**唯一契约**。改实现前先读这里；与设计文档冲突时，以实现路线说明为准（见 §1.2）。

## 1. 实施路线

### 1.1 一句话

滚动驱动的垂直「时间之柱」：7 个**浮动低模沙盘平台**（上=远古，下=现代）沿 Y 轴堆叠，相机沿螺旋路径下降；每层平台由**声明式场景数据**程序化生成（Three.js 基础几何 + flat shading），4 个知识点的热点可点击弹出数据卡。

### 1.2 与设计文档的偏差（已确认实施路线）

| 设计文档           | 本实现                                                                                              | 原因                                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Blender → glb 建模 | **程序化 Low-poly**（Three.js 基础几何 + 顶点色/flat shading），由 `src/content/scenes/*.json` 声明 | 无 Blender 资产管线；声明式场景同样满足「内容即数据、代码是通用解释器」（设计文档 §13），且零资产体积、可维护性更好 |

`model` 字段暂保留为未来 glb 插槽，渲染器不读取。若将来接入 glb：在 `SceneRenderer` 内加 glb 分支即可，热点锚点机制不变。

## 3. 世界坐标与平台

- 每个时代一块平台，**平台顶面即 y=0**（道具、锚点都在其局部坐标内，渲染器整体平移到 `(0, -index*28, 0)`）。
- 平台半径 **14**，顶面圆盘 + 下方向下收拢的岩石底座（浮动岛）。
- 道具坐标 `pos: [x, y, z]`，建议 `|x|,|z| ≤ 10.5`（越界会被验证脚本警告）；`y` 默认 0（贴地），悬浮道具（飞机、云、手机）可给正 y。
- **四象限与四维度的对应固定**（跨时代保持一致，便于对比）：

| 维度                      | 象限 | 区域                       |
| ------------------------- | ---- | -------------------------- |
| 能源与工具 `energy-tool`  | 西北 | x ≤ −2, z ≤ −2             |
| 食物 `food`               | 西南 | x ≤ −2, z ≥ 2              |
| 居住 `shelter`            | 东北 | x ≥ 2, z ≤ −2              |
| 交通 `transport`          | 东南 | x ≥ 2, z ≥ 2               |
| 通讯（信息图层，若落 3D） | 中心 | 平台中心 ±3 内，不占四象限 |

- 平台中央保留直径 4 的空地（可放标志物，如篝火/纪念碑）。
- 相机每层从平台外围绕行，角度随时代旋转（螺旋下降），所以**每个道具都会被看到**，不要只朝 +Z 摆正面。

## 4. 场景数据 schema（`src/content/scenes/<era-id>.json`）

```jsonc
{
  "eraId": "agriculture", // 必须等于 eras.json 里同一条的 id
  "ground": {
    "top": "#7C8B4A", // 顶面草土色
    "side": "#5E4A30", // 盘侧土层
    "underside": "#332A1E", // 底部岩石
    "scatter": { "type": "grass-tuft", "count": 14 }, // 可选：自动随机散布的小装饰
  },
  "props": [
    {
      "type": "field", // 道具类型 id（props 注册表里的 key）
      "pos": [-6.5, 0, 6.0], // [x, y, z]，y=0 贴地
      "rotY": 0.35, // 弧度，绕 Y 轴
      "scale": 1.1, // 统一缩放，默认 1
      "anchorId": "field", // 可选：热点锚点 id，必须等于某个 knowledgePoint 的 anchor.mesh
      "params": { "rows": 5 }, // 可选：道具自定义参数
    },
  ],
}
```

**硬性要求**

1. `eraId` 与文件名一致、与 `eras.json` 的 `id` 一致。
2. 每个时代的**必需锚点**（见 §6）必须由某个 prop 的 `anchorId` 提供，否则该时代相应热点会丢失。
3. 每个时代 total props 建议 **18–30 个**，四象限都有内容。
4. 只使用 §7 分配给自己的 prop 类型 id，或共享池里的 id。**不要**自创与别人重名的 id。

## 5. 道具 API（`src/scene/primitives.ts`）

道具 = 纯函数。渲染器已把道具组放到正确位置，道具内部**以原点为支点、y=0 为地面**搭建。

```ts
import type { BuildCtx, PropBuilder, PropParams } from '../primitives';

export const builders: Record<string, PropBuilder> = {
  // 例：一口篝火
  fire: (ctx, params) => {
    const h = num(params, 'h', 1.0);
    // ctx 提供现成图元（全部 flat shading、自动 castShadow）
    ctx.cyl(0.9, 1.1, 0.28, '#4A3524', [0, 0.14, 0]); // 灰烬底盘
    ctx.cone(0.34 * h, 1.1 * h, '#F5A25A', [0, 0.75 * h, 0], undefined, 6); // 火苗外焰
    ctx.cone(0.2 * h, 0.7 * h, '#FFE08A', [0, 0.6 * h, 0], undefined, 6); // 火苗内焰
    ctx.mat('#FFB35C', { emissive: '#FF7A1F', emissiveIntensity: 1.4 }); // 发光材质可复用
    return { anchorY: 1.1 }; // 热点锚点高（默认 1.2）
  },
};
```

### 5.1 `BuildCtx` 方法（全部返回 `THREE.Mesh`，自动加入道具组并 cast/receive shadow）

```ts
interface BuildCtx {
  readonly root: THREE.Group;
  readonly rand: () => number; // 确定性随机（同一道具每次生成一致）
  mat(color: string, opts?: MatOptions): THREE.Material; // 颜色/材质缓存，务必用它取材质
  addMesh(
    geo: THREE.BufferGeometry,
    color: string,
    pos?: Vec3,
    rot?: Vec3,
    scale?: Vec3,
    opts?: MatOptions,
  ): THREE.Mesh;
  box(
    w: number,
    h: number,
    d: number,
    color: string,
    pos?: Vec3,
    rot?: Vec3,
    opts?: MatOptions,
  ): THREE.Mesh;
  cyl(
    rTop: number,
    rBottom: number,
    h: number,
    color: string,
    pos?: Vec3,
    rot?: Vec3,
    seg?: number,
    opts?: MatOptions,
  ): THREE.Mesh;
  cone(
    r: number,
    h: number,
    color: string,
    pos?: Vec3,
    rot?: Vec3,
    seg?: number,
    opts?: MatOptions,
  ): THREE.Mesh;
  sphere(r: number, color: string, pos?: Vec3, seg?: number, opts?: MatOptions): THREE.Mesh;
  ico(r: number, color: string, pos?: Vec3, detail?: number, opts?: MatOptions): THREE.Mesh; // 低模球（岩石/树冠首选）
  plane(w: number, d: number, color: string, pos?: Vec3, rot?: Vec3, opts?: MatOptions): THREE.Mesh; // 水平朝向（rotation.x=-PI/2 已处理）
}

interface MatOptions {
  emissive?: string; // 发光色：火、灯、屏幕、能量
  emissiveIntensity?: number;
  transparent?: boolean;
  opacity?: number;
  side?: THREE.Side;
}
```

参数读取助手：`num(params, key, fallback)`、`str(params, key, fallback)`、`bool(params, key, fallback)`。

### 5.2 风格规范

- **尺寸单位：米（世界单位）**；人物约 1.7 高，房子 3–5 高，火车 3 高，摩天楼 8–14 高。
- 一律 flat shading（引擎默认）、低面数：球体 `seg=6~8`、圆柱 `seg=6~8`、圆锥 `seg=5~8`。单个道具三角面建议 ≤ 600。
- 颜色用**明快低饱和**的卡通色；每个时代以 `themeColor` 为点缀色（少量高饱和），主色用中性色。
- 发光（emissive）只用于：火、灯、屏幕、能量、新能源，克制。
- 不要用贴图、不要加载外部资源、不要用 `Math.random()`（用 `ctx.rand()`）。
- 不要给道具设置位置（`ctx.root` 由渲染器定位）——道具内部平移到世界坐标会导致锚点错位。

## 6. 各时代必需锚点（`anchorId`）

来自 `src/content/eras.json` 的 `knowledgePoints[].anchor.mesh`，**缺一不可**：

| eraId             | 必需 anchorId                                  | 语义                                 |
| ----------------- | ---------------------------------------------- | ------------------------------------ |
| `hunter-gatherer` | `fire` `cave` `roast`                          | 篝火、洞穴、篝火旁的烤肉架(火烤熟食) |
| `agriculture`     | `field` `rice-paddy` `wheel` `tablet`          | 农田、水稻田、轮子、泥板             |

## 8. UI 契约（`src/ui/**`）

UI 用**原生 TS + DOM**，不引入框架。样式集中在 `src/ui/styles.css`（由 `main.ts` 引入）。所有组件都是工厂函数，接收 `root: HTMLElement` 与回调，返回控制器。

```ts
// src/ui/IntroCard.ts
export interface IntroCard {
  setVisible(v: boolean): void;
}
export function createIntroCard(
  root: HTMLElement,
  opts: { title: string; subtitle: string; hint: string },
): IntroCard;

// src/ui/InfoBar.ts —— 左下角时代信息卡，切换时淡入淡出
export interface EraInfo {
  index: number;
  total: number;
  title: string;
  subtitle: string;
  themeColor: string;
}
export interface InfoBar {
  setEra(era: EraInfo): void;
  hide(): void;
}
export function createInfoBar(root: HTMLElement): InfoBar;

// src/ui/TimelineSlider.ts —— 左侧垂直时间轴，7 个主题色节点
export interface TimelineSlider {
  setActive(index: number): void; // -1 = 序章，无高亮
  setProgress(p: number): void; // 0..1，可选：节点间进度条
  dispose(): void;
}
export function createTimelineSlider(
  root: HTMLElement,
  eras: { title: string; themeColor: string }[],
  onSelect: (index: number) => void,
): TimelineSlider;

// src/ui/HotspotLayer.ts —— DOM 热点层（renderer 每帧喂屏幕坐标）
export interface HotspotItem {
  kpId: string;
  title: string;
  themeColor: string;
}
export interface HotspotFrame {
  kpId: string;
  x: number;
  y: number;
  visible: boolean;
  scale: number;
} // x/y 为画布 CSS 像素
export interface HotspotLayer {
  setItems(items: HotspotItem[]): void;
  sync(frames: HotspotFrame[]): void;
}
export function createHotspotLayer(root: HTMLElement, onOpen: (kpId: string) => void): HotspotLayer;

// src/ui/DataModal.ts —— 居中浮层：标题 + 正文 + 数据行(含来源链接) + 关闭

  title: string;
  body: string;
  themeColor: string;
  eraTitle: string;
  data: { label: string; value: string; source?: string }[];
}
export interface DataModal {
  open(content: ModalContent): void;
  close(): void;
  isOpen(): boolean;
  onClose(cb: () => void): void;

// src/ui/EndCard.ts —— 结语卡 + 重播按钮

  setVisible(v: boolean): void;
}
export function createEndCard(root: HTMLElement, onReplay: () => void): EndCard;

// src/ui/AutoTour.ts —— 自动导览按钮（可选增强）
export interface AutoTour {
  setVisible(v: boolean): void;
  setPlaying(v: boolean): void;
}
export function createAutoTour(root: HTMLElement, onToggle: () => void): AutoTour;
```

**DOM 约定**

- 所有 UI 挂到 `#ui-root`（`position: fixed; inset: 0; pointer-events: none; z-index: 10`），交互元素单独 `pointer-events: auto`。
- UI 不得访问 Three.js 对象、不得 import `src/core`、`src/scene`；只消费上面这些纯数据。
- 无障碍：滑块节点是 `<button>`，可 Tab 聚焦，有 `aria-label`；浮层 `role="dialog"`，ESC 关闭；文字对比度合格。
- 视觉：深色中性底板 `#14161A`，半透明卡片，主题色只做点缀（标题竖条/节点/强调）。字体 `system-ui`。移动端不做适配（桌面 1280+ 设计）。
- 所有动画用 CSS transition / keyframes，不引入 GSAP。
- `src/ui/styles.css` 里请放**全部** UI 样式（含 `#ui-root`、按钮、卡片、热点脉冲 keyframes）。

`src/ui/types.ts` 可放上述公共类型（或各自模块内定义，只要 `main.ts` 能 import 到）。

## 9. 校验与验收

每个人交付前自查：

```powershell
npx tsc --noEmit          # 我的文件无类型错误（别人的文件可能正在写，忽略非我文件的错误）
npx eslint <我的文件>      # 无 error
```

Lead 集成后统一跑：

```powershell
npm run typecheck
npm run lint
npm run build
npm run validate          # 内容/场景/锚点校验脚本（T 提供）
```

**不要 git commit / push**（Lead 统一提交）。不要执行 `npm install` 之外的全局改动；需要新依赖先问 Lead（T 除外，T 负责 `package.json`）。

**场景质量红线（会被截图检查）**

1. 平台四象限都有内容，没有大片空白。
2. 同象限的元素属于同一维度，且不与平台边缘/其他道具明显穿插。
3. 每个模型从侧面看有体积感（不是平面拼贴），贴地不悬空。
4. 必需锚点存在且锚点高度合理（热点浮在物体上方 1–2 单位，不埋进地里）。
5. 主题色出现在该时代至少 2 个元素上（提示时代辨识度）。
